Code organization and development checks¶

Declarack separates framework mechanisms from adapter semantics and groups UI code by the feature a contributor is changing. Prefer cohesive modules with explicit dependencies over file-size targets, forwarding wrappers, or a generic service locator.

Backend¶

Location Owns
server.py, api_support.py Application composition, endpoints, startup and response/request handling
auth/store.py, auth/http.py, auth/__main__.py Database administrators, password hashes, bootstrap, sessions/throttling, cookie/CSRF HTTP boundary and host password recovery
identity.py Request actor context for recorded operation-plan metadata
serving.py Single-listener Cheroot host, native TLS identity and explicit one-hop proxy trust
adapter_registry.py Package discovery, dependencies and connection/executor registration
configuration_types.py YAML parsing and shared configuration values
input_schema.py Operation input declarations and execution-time validation
dashboard_core.py Assemble enabled features, target capabilities, public metadata and operation dispatch
view_schema.py, workflow_schema.py, form_options.py Renderer/workflow contracts and permitted lookup operations
checks.py, operation_runs.py, batches.py, bulk_actions.py Distinct framework execution features
terminal_sessions.py, file_tree.py Bounded PTY sessions and rooted read-only filesystem mechanisms
adapters/docker/context.py Deployment settings and request-local Docker target context
adapters/docker/client.py Socket transport and manager checks
adapters/docker/resources.py Docker inventory/network inspection and Swarm config/secret operations
adapters/docker/legacy_routes.py Translate legacy HTTP requests into calls to the same services used by configured operations
adapters/docker/lifecycle.py Tunnel retention and expired node-job cleanup
adapters/swarm/stacks.py Stack source persistence, credential encryption, source retrieval, deploy/replace and reviewed volume cleanup
adapters/swarm/jobs.py Manager-scheduled node jobs, bounded collectors and job cleanup
adapters/swarm/workflows.py Swarm overview and resource workflow dispatch
adapters/docker/runtime.py Compose the built-in service instances and default installation settings

The runtime composition module wires explicit collaborators. For example, StackService(context, client, jobs) receives the services it uses. Service implementations do not import the HTTP host, Flask, or their composition module. A blueprint translates requests into explicit service arguments; services do not read a request object to discover what an operation means. This lets configured operations, old URLs and tests exercise one implementation.

Core errors are in errors.py. Import helpers from their owning modules rather than relying on dashboard_core.py to re-export every backend utility. Additional adapters still use the same manifest and registration interface.

Frontend¶

frontend/src/
  app/                    # Shell, navigation, header and workspace view selection
  features/
    resources/            # Generic inventory, details, actions, related rows,
                          # terminal/file views and action state
    dashboards/           # Configured multi-target pages and charts
    environments/         # Environment groups and target summaries
    auth/                 # Session gate, login and installation administrators
    settings/             # Source editing and integration setup
    checks/               # Check state and history
    operations/           # Run history and multi-target batches
    workflows/            # Configured workflow editor
  components/ui/          # Shared presentation primitives and controls
  lib/                    # Pure mapping, sorting, routing and execution helpers

Within the resource feature, resource-page.jsx coordinates collection and view state. resource-table.jsx, resource-toolbar.jsx, resource-action-dialog.jsx, resource-summary.jsx, resource-workflow.jsx and resource-session.jsx render specific parts. use-resource-actions.js owns action review, execution and output state. The shell delegates view choice to workspace-content.jsx using explicit branches rather than a nested chain of JSX ternaries.

The main inventory, dashboard panels and related tables all use lib/table-rows.mjs for JSONata cell/filter/sort/tone/link/eligibility mapping, SortableHeader for sorting controls and TablePagination for page controls. view-values.mjs owns shared value formatting and path access. Keep the actual column definitions, operation bindings and resource-specific wording in YAML.

An extraction should have a recognizable responsibility. Do not split a function into several files just to reduce line counts or pass the whole application as a mutable dependency object. Prefer passing the collaborators or props a feature uses, and keep state close to its owner.

Local verification¶

From the repository root, using your existing Python virtual environment:

.venv/bin/pip install -r requirements-dev.txt
npm --prefix frontend ci
.venv/bin/ruff check backend tools
npm --prefix frontend run lint
npm --prefix frontend run format:check
.venv/bin/python -m unittest discover -s backend/tests
npm --prefix frontend test
npm --prefix frontend run test:views
npm --prefix frontend run build
.venv/bin/python tools/check_tutorial.py

Use ruff check --fix backend tools to remove unused imports and sort import blocks. Use npm --prefix frontend run format for consistent frontend formatting. Ruff checks undefined names and import mistakes; ESLint checks undefined/unused names and JSX usage/keys. Prettier provides one frontend format. These are development tools; none are added to the final runtime image's Python environment.

The Build workflow runs the static checks, formatting check and tests before its image build. The Documentation workflow separately verifies the runnable tutorial and documentation links. Tests cover target context isolation, service dependency boundaries, cleanup failures, default Docker mode detection, shared table mapping, and server-rendered feature compositions. Browser globals that can hide missing props (such as bare navigation) are rejected by the frontend lint configuration.

After changing integration execution, also run the relevant live workflow: a unit test cannot prove that a Swarm node can start its helper image or that a terminal relay can reach a running worker task. The helper image must match the controller.

Configuration editing is grouped in backend/configuration/: editor.py validates reviews and revision-checked saves, history.py stores bounded local snapshots, and routes.py exposes their HTTP boundary without owning active configuration state. The frontend settings feature composes separate review and revision-history components.

backend/sources/git.py isolates Git fetch/ref resolution and bounded source extraction from the Swarm adapter. Docker deployment credential profiles live in backend/adapters/docker/credentials.py, shared by image pulls, Compose CLI commands, Swarm deploys and service edits. UI fields remain adapter YAML.

backend/storage/ owns SQLAlchemy Core connections, Alembic migrations, versioned documents, and explicit legacy-import/backend-transfer commands. Framework stores and adapter source repositories use it; adapters receive services["storage"]. runtime_settings.py owns the data-directory setting independently of Docker. See storage setup and boundaries for SQLite/PostgreSQL behavior.

Environment grouping and root navigation validation live in backend/environments.py; checks retain monitoring definitions and execution, and batches retain bounded fan-out.

backend/configuration/environments.py projects structured environment forms into source-file drafts for the shared configuration editor. The dedicated frontend settings page is features/settings/environment-editor.jsx.

configuration/managed.py owns immutable YAML document revisions and saved/active database pointers. configuration/writeback.py handles journal recovery and local file publication. Storage write transactions reserve the SQLite writer before reading state; PostgreSQL uses normal transactional locking.

Account and transport boundaries¶

auth/store.py owns account validation, scrypt password hashing, first-user-only bootstrap, hashed opaque sessions, shared login throttling and bounded account audit documents in framework.auth.audit (1,000 retained; activity reads return 100). Account writes revalidate the actual session hash under the account lock after password hashing, preventing revoked sessions from finishing queued writes. auth/http.py installs the cookie/CSRF boundary and account endpoints; auth/__main__.py provides host-only password recovery. Migration 0002 adds the four authentication tables. Login accounts are distinct from configuration credential profiles. identity.py supplies metadata.actor to recorded operation plans, and batches.py propagates ContextVars into fan-out threads to preserve that actor. Bounded account activity plus plan metadata is not a complete generic resource audit log; direct calls do not all produce recorded plans.

serving.py loads TLS certificates at startup, persists self-signed files under <DECLARACK_DATA>/tls, and accepts forwarded proto/client information only from explicit immediate-proxy IPs/CIDRs. The frontend features/auth/session-gate.jsx unmounts protected children after logout, the session expiry timer or an API 401; the header owns the signed-in username and sign-out control. users-page.jsx owns the dedicated #/settings/~users list, ~new creation and user-ID detail routes, consequential-change confirmations and account-filtered activity. The shell owns the shared refresh button; users/activity data subscribe to its revision. See users and TLS for maintained operator behavior.

Action output presentation uses backend/view_schema.py for configuration validation, frontend/src/lib/action-output.mjs for identity/extraction and result state transitions, features/resources/use-resource-actions.js for execution, and components/ui/action-output.jsx for shared viewers. ResourceTable anchors each result beneath its stable row; adapters do not own output JSX.
