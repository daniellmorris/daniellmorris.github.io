Reusable workflows for resource management¶

This expansion closes management gaps through reusable framework capabilities. Docker resource rules remain in adapter executors and feature/operation YAML; the React workflow renderer does not contain service, node, or network update logic.

What the built-in Docker configurations now provide¶

  • Swarm service editing: image, environment, service/container labels, entrypoint, arguments, mounts, published ports, network attachments, resource constraints, placement, restart/update policy, health-check settings, logging, and existing config/secret reference objects.
  • Version-checked service rollback to Docker's previous specification.
  • Version-checked node role, availability and labels editing; the adapter refuses demotion of the last manager. Existing availability actions remain available.
  • Network creation defaults to overlay in Swarm and bridge in Standalone. Driver, internal and attachable controls combine with expert JSON for IPAM, labels, driver options, IPv6 and other supported network-create properties.
  • Container creation accepts expert Docker create options, including environment, command/entrypoint, ports, mounts, resource limits, restart policy, labels, health-check configuration and network attachments. Name/image stay dedicated fields, and the image field takes precedence over options.Image.

The advanced JSON fields expose Docker structures rather than a guided editor for every Docker option. Standalone container edit/replace/duplicate now uses tracked server-owned plans, structured row editors, and retained backups. Creating a container does not automatically start it or pull a missing image. Swarm engine-level container creation still acts on the manager engine. Service creation, private registry credential management and GitOps remain gaps.

Typed operation inputs and defaults¶

Operation schemas support type: object alongside existing types. Objects must be JSON-serializable, finite JSON under 700 KiB; the HTTP request body limit also applies. A schema default supplies an omitted input, is validated at configuration load, and is copied for each call. An explicitly supplied invalid value is not replaced by a default. Lists retain their default 20-item limit unless a validated max_items (1–1000) overrides it.

inputs:
  options: {type: object, default: {}}
  attachable: {type: boolean, default: false}

JSONata request bodies¶

HTTP and Docker request bindings can use a JSONata body_expression instead of a body template. The evaluation root is the validated input object. This allows config authors to merge optional structured settings without adding executors. Both mechanisms cannot be supplied together. Expressions are parsed on config load; evaluation uses a 1-second guard, depth 100, and sequence limit 10,000.

executor: docker.request
method: POST
path: /containers/create
query: {name: '{name}'}
body_expression: '$merge([options, {"Image": image}])'

The existing body template syntax remains supported. These mapping guards are not process isolation and assume trusted configuration authors.

Workflow building blocks¶

Setting Purpose
initial Field-key to JSONata-expression mapping evaluated against the inspected entry.
defaults Initial field values; JSON fields implicitly default to an object/array.
defaults_by_provider Provider-specific defaults, before entry and initial values.
Field type: json Editable typed structured input with parse/type errors.
Field json_type: object/array Expected root JSON shape; default object.
Action map Input-name to JSONata-expression mapping evaluated against workflow context.
review Context path to a {before, after, version, warnings} preview object.
embedded: true Render the workflow within a normal detail page, preserving its actions and resource sections.
Section collapsible / collapsed Native collapsible groups, optionally initially closed.

Context contains form, entry, results, creating, and provider. In action mappings, form JSON fields are parsed objects/arrays, not textarea strings. Malformed, non-finite or incorrectly shaped JSON prevents workflow execution. Missing/null initialized JSON objects/arrays use the configured empty defaults. Values are merged in this order: implicit structured defaults, workflow defaults, provider defaults, inspected entry, then defined initial results.

Action values are built from static values, then JSONata map, then path-based bind. Mappings are awaited before execution. Existing binds still work, including nested paths such as entry.Version.Index. Ordinary row actions also support nested row bindings. The generic action dialog and batch page accept object inputs.

review displays changed paths, including absent values and array replacements. The apply confirmation repeats the reviewed diff. Editing a field invalidates the preview and marks the form dirty; reviewed values must be previewed again. For other workflows, changes_source retains its existing invalidation behavior. An action with reload: true can set reload_on_error: false to preserve its draft on failure; reviewed Swarm editors use this behavior. Refresh explicitly when a version conflict requires a fresh inspection. Backend executors still enforce concurrency and allowed mutations: a client-side diff by itself does not authorize or validate a write.

Add a guided field without a new React component¶

This is a configuration fragment for an existing standalone Docker target. It reuses shipped operations to turn a friendly memory field into Docker's byte count. No new Python executor or JSX branch is required. Enable container_launcher in the target's feature list (lists replace earlier lists when merging).

features:
  container_launcher:
    title: Container launcher
    operation: containers.list
    columns:
      - {label: Name, value: '$join(Names, ", ")'}
      - {label: State, value: State}
    workflow:
      create_only: true
      create_label: Create container
      defaults: {memory_mb: 64, env: []}
      fields:
        - {key: name, label: Name, required: true}
        - {key: image, label: Local image, required: true}
        - {key: memory_mb, label: Memory MB, type: number, required: true}
        - {key: env, label: Environment variables, type: json, json_type: array}
      actions:
        - label: Create stopped container
          operation: containers.create
          bind: {name: form.name, image: form.image}
          map:
            options: '{"Env": form.env, "HostConfig": {"Memory": $number(form.memory_mb) * 1000000}}'
          validate: true
          back: true
          primary: true

Swarm review/apply behavior¶

The swarm.manage adapter executor uses YAML-defined editable paths and value kinds. Preview reads the current specification, requires the explicit inspected version, copies it, and changes only declared fields. Unedited and unknown fields are retained. Structured fields replace their selected subtree, so editing a labels object intentionally replaces that labels map; deleted keys appear in the diff.

Preview returns the reviewed changes, current version, full before/after specs, warnings and a digest. Apply re-reads the resource and validates both the version and digest before submitting an optimistic Docker update. No-op previews are identified and do not issue updates. Docker may still reject policy/shape/resource constraints: preview is not a Docker dry-run or an image-availability check.

A changed version requires refreshing details and previewing again. Docker can change a service version as update/rollback status evolves, so a conflict can occur without another person editing it. Apply and rollback acknowledge the Docker API request, not eventual task convergence; inspect tasks and errors afterward.

For stack-owned services, the adapter warns that later Compose deployment can overwrite direct edits. Update the source configuration too. Config/secret fields refer to existing IDs; they do not create secrets or reveal secret contents. Rollback requires PreviousSpec and uses Docker's rollback=previous behavior, including its previous-spec registry-auth reference. This does not add a registry credential UI.
