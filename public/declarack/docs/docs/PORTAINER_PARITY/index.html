Portainer parity review: Docker Standalone and Swarm¶

Reviewed 2026-11-20 against Portainer's current online Docker documentation and Declarack's adapter definitions, execution code, and UI. This is a capability review, not a claim that every supported operation has a dedicated end-to-end integration test. Portainer documentation spans Community and Business features; items explicitly documented as Business-only are noted. Kubernetes, Podman, and Edge fleet management are outside this Docker/Swarm comparison.

Conclusion: Declarack does not have full Portainer parity. It covers common inventory, inspection, lifecycle operations, Compose/stack management, and remote Swarm terminals. Advanced deployment editors, cluster-wide engine-resource management, registry workflows, GitOps automation, and multi-user governance are substantial gaps. Recent additions include a read-only volume file browser, configurable multi-target operation pages, and reviewed service/node editing built on reusable workflow extensions. Network and container creation now accept structured options. These improvements do not make the overall product equivalent to Portainer.

Legend: Covered = a shipped operation/UI handles the stated scope; Partial = narrower scope or less complete UI; Missing = no first-class shipped workflow. A Docker API endpoint being technically callable from custom YAML does not count as a finished management feature.

Docker Standalone¶

Portainer reference: Docker resource overview, container details, advanced container settings, edit/duplicate, statistics.

Capability Declarack Actual scope / remaining gap
Container inventory, details, full inspect JSON Covered Config-defined tables, detail fields, JSON inspection, search, sorting, page-size selection.
Start, stop, restart, pause, resume, rename, remove Covered Individual container actions with confirmations for destructive actions.
Create a container Partial Name/image fields now combine with typed expert Docker create JSON. Creation stays stopped and does not pull missing images.
Advanced create settings Partial — expanded Typed create-options JSON now supports command, env, ports, mounts, restart/logging policies, limits, devices, DNS, capabilities and health checks. Dedicated guided controls for all options are still missing.
Edit/replace or duplicate an existing container Partial — implemented Reviewed standalone cloning/replacement, retained backups, explicit recovery and tracked runs. Fresh-storage duplicate defaults; advanced JSON for many settings. Compose and Swarm use their deployment workflows. See limits.
Interactive container console Covered Shell/user selection, interactive I/O and resize through Docker exec.
Attach to the primary container process Missing Exec terminal is not process attachment.
Container logs Partial Fetchable output, not a full live-tail/filter/download log viewer.
Container statistics Partial Snapshot operation / raw data; not equivalent to live CPU, memory, network, I/O charts and process listings.
Container health Partial Inspect state exposes Docker health and health-check output; no full health-check editor or historical charts.
Commit a running container into an image Missing No shipped commit workflow.
Container webhooks Missing No external lifecycle/redeploy webhook endpoint.

Portainer reference: images, image building, pruning, networks, volume browsing.

Capability Declarack Actual scope / remaining gap
Image list, inspect, size display Covered Sizes formatted in MB/GB while sorting uses underlying bytes.
Pull, tag, remove images Covered Shipped standalone workflows/actions.
Build images from Dockerfile, upload, or Git Missing No image build UI or build-context management.
Import/export images Missing No archive workflow.
Push images / authenticated registry selection Missing No first-class registry credentials/push management.
Detect newer image versions Missing No registry comparison indicator.
Prune dangling/unused images and build cache Missing Disk usage is visible; individual removal does not equal reviewed bulk pruning.
Network inventory, inspect, remove Covered Engine-scope resources.
Network creation Partial Driver/internal/attachable fields, bridge default on Standalone, overlay default in Swarm; expert JSON supports IPAM, labels, options and IPv6. No fully guided editor for every property.
Connect/disconnect containers to/from networks Covered Individual network actions.
Volume inventory, inspect, attachments Covered Local volume inventory with references to attached containers.
Volume size measurement Covered Explicit collection; unavailable data remains unavailable rather than zero.
Create/remove volumes Partial Basic local-driver creation; no general storage-driver/options editor.
Browse volume directories Partial — added Read-only directory navigation, file preview, and bounded downloads. No host-root mount is required.
Upload, rename, edit, delete volume files Missing Portainer provides upload/download/rename/delete. Declarack intentionally ships read-only browsing first.
Host system/device/filesystem management Partial Disk usage and configurable metrics; no general host device browser or root-filesystem management.

Portainer's volume browser requires Swarm or its Agent according to the linked documentation. Declarack uses short-lived helpers on Standalone and node-pinned jobs in Swarm. Their deployment requirements and writable capabilities differ.

Portainer reference: stack deployment, stack inspection/editing, migration/duplication/rename.

Capability Declarack Actual scope / remaining gap
Discover existing Compose projects Covered Docker Compose project discovery, project containers and source metadata.
View Compose YAML from host Partial Requires accessible reported host paths through an explicitly configured host mount, or a saved source. Docker labels do not contain the full Compose file.
Inline or mounted-folder Compose sources Covered Saved source, preview/validation, reviewed apply.
Start, stop, restart, up, down, remove orphans Covered Config-defined project workflow.
Git-backed standalone Compose projects Missing Current standalone editor supports inline/folder sources, unlike the Swarm GitHub stack workflow.
Arbitrary Git providers/branches, multiple Compose overlays Missing No equivalent of Portainer's broader source/ref/multiple-file deployment UI.
Dedicated .env editing/import and deployment-variable management Missing Not a first-class project settings workflow.
Automatic Git polling and redeploy webhooks Missing Deployments remain explicit. Scheduled checks do not redeploy applications.
Template catalog, deploy-from-template, save-as-template Missing Example system configurations are not an application-template catalog.
Cross-environment migration/duplicate/rename wizard Missing No purpose-built transfer workflow or persistent-data migration.

Docker Swarm¶

Portainer reference: services, service configuration, tasks, Swarm node details, cluster visualizer, configs, secrets.

Capability Declarack Actual scope / remaining gap
Services, nodes, tasks inventory and inspect Covered Tables, details, raw JSON, desired/running replica visibility.
Expand services into task/container rows Covered Task-based worker/container associations.
Scale, force restart, remove a service Covered Versioned service updates for supported actions.
Service logs Partial Fetchable output; not a complete live log/statistics experience.
Create a service with a dedicated form Missing Deploy through Compose stacks instead.
Edit service image, env, labels, mounts, ports, networks, secrets/config attachments Partial — added Version-checked YAML-defined editor with typed structured fields, preview and apply. Includes command/args, logging and health settings. More guided fields and remaining container-spec settings are still gaps.
Service resources, placement, update/restart policies Partial Live editor now supports placement, resource, restart/update-policy JSON with preview; not a guided control for every subfield.
Service rollback Covered — added Explicit-version rollback, previous-spec check, confirmation, Docker server-side rollback.
Service redeploy webhooks Missing No external webhook trigger.
Node availability (active/pause/drain) Covered Versioned node availability action.
Node role promotion/demotion and label editing Covered — added Version-checked role/labels/availability editor with preview; last-manager demotion is refused.
Initialize/join/leave Swarm, token/CA/autolock management Missing No complete cluster-administration interface.
Cluster topology/task placement visualizer Missing Tables/relations are available; no equivalent visualizer.
Remote worker container terminal Covered Task identity resolves node/container; same-image node-local relay jobs. Worker SSH is not used.
Cluster-wide container/image/network lifecycle management Partial Generic Docker API operations target the manager engine. Task associations and worker terminals do not make every engine resource/action cluster-wide.
Swarm overlay network creation/settings Partial — added Correct overlay default, driver and attachable controls, and expert create JSON. Existing networks still follow Docker’s immutability limits.
Configs and secrets list/create/remove/inspect Covered Swarm only. Docker does not return secret contents. Neither appears as native standalone Docker resources.
Per-node volume inventory/sizes/create/remove Covered Node-selected or aggregated reads through jobs. Writes select one node.
Per-node volume file browsing Partial — added Explicit single-node read-only job mounts the selected volume. No writable file manager.
On-demand node metrics Covered Same-image jobs aggregate node snapshots; no worker SSH or continuous metrics retention by default.
Host disks/PCI devices/root filesystem Missing No full host-management interface.

Swarm stacks and source persistence¶

Portainer reference: stack sources, deployment options and GitOps.

Capability Declarack Actual scope / remaining gap
Inline YAML, mounted folder, GitHub source Covered Stack workflow separates source settings from deployment.
Private GitHub username/PAT Covered Source metadata and encrypted token/key are target-scoped records in the shared SQLite/PostgreSQL database; redeploy retrieves the saved source and credential. See storage migration guidance.
Arbitrary Git ref/branch/provider support Partial Current checkout resolves tags (refs/tags/<tag>); do not advertise general ref support.
Deploy/update/remove/replace, selected volume cleanup, orphan cleanup Covered Reviewed source digest, deployment and cleanup workflow.
Stack services/tasks/networks/configs/secrets/volume references Covered Related-resource views distinguish ownership/references; declared volume references are not physical node inventory.
Private image registry authentication Missing GitHub PAT source access does not authenticate container registries.
Automatic GitOps, webhooks, deployment windows Missing Explicit deploy only; checks scheduler is not a GitOps controller.
Relative Git-repository bind mount provisioning Missing No equivalent of Portainer's documented Business-only relative-path provisioning.
Application templates and cross-target migrations Missing Examples/config merging are different capabilities.

Platform and governance gaps¶

References: registries, Business RBAC, authentication.

Declarack has database-backed local administrator accounts, cookie sessions with CSRF protection, native file/self-signed TLS, Docker-secret/file credential references, configuration editing and reload, target/environment separation, custom multi-target pages, persisted checks, and now bounded multi-target operation pages. These do not provide Portainer's user/team resource ownership, granular RBAC, LDAP/AD/OAuth, registry credential lifecycle, Business registry browsing/management, access-policy administration, or audit-log governance. All administrators have full installation, credential and workload access; environment grouping is not authorization. Settings supports create/disable/enable/password reset/session revocation, but no account deletion, signup or role selection. Recorded operation plans include metadata.actor, including through batch fan-out. Bounded account activity records creation, password reset, disable/enable, session revocation and host recovery, with actor identity and no secrets (1,000 retained; newest 100 available read-only). These account events and plan metadata are not a complete generic resource audit log; simple direct calls do not all produce recorded plans. HTTP Basic Auth is unsupported. TLS has no ACME, automatic renewal or redirect listener. Demo bypasses login and explicitly disallows user management. See administrators and TLS. No full Portainer Server backup/restore wizard, licensing system, Edge Agent/tunnel fleet provisioning, offline snapshots, or remote agent lifecycle management is claimed.

Recommended next work¶

  1. Extend the new reviewed service editor with more guided field types and remaining service settings (for example user, working directory, hostname/DNS), then add a dedicated service creation flow. Rollback and basic editing are now shipped.
  2. Expand guided controls on the shipped standalone edit/replace/duplicate flow; retain its explicit data/network handling and recovery checks.
  3. Introduce registry credential references usable by image and stack deployment; separate registry authentication from Git authentication.
  4. Make container/image/network node scope explicit everywhere; add selected-node operations before claiming cluster-wide engine management.
  5. Add reviewed pruning with resource counts and storage estimates, without automatically deleting attached volumes or active build caches.
  6. Add generic Git refs/providers, standalone Git Compose sources, and deployment webhooks before a full GitOps controller.
  7. Expand the file browser to writable operations only with clear permissions, overwrite checks, confirmations, and backup expectations.
  8. Build team authorization and audit history before marketing multi-tenant access.

A single percentage would hide material differences. Track individual workflows, node scope, source modes, and governance separately.

Registry/Git follow-up (2026-11-21)¶

Target-scoped registry credential files now support image pulls, standalone Compose CLI operations, Swarm stack deployment with worker auth forwarding, and service edits. Swarm stacks gain general HTTPS/SSH Git URLs with branches, tags and full commit IDs. General Git uses saved metadata plus reusable mounted credential references; legacy GitHub tag/PAT storage remains available. This supersedes the missing-registry and tag-only rows above for these scopes. Registry browsing/push, standalone Git Compose sources, automatic GitOps, webhooks and repository bind-mount provisioning remain gaps. See setup and persistence.

Inventory scope update¶

Containers and networks now use node-local Swarm jobs for selected/all-node inventory, with node-qualified identities and partial failure reporting. Worker inspection and running task terminals are available directly from container rows. Direct worker lifecycle/network mutation is still not covered: those actions use the connected manager engine, with service actions governing desired task state. This expands inventory coverage without implying that every Docker action is cluster-wide. See the scope contract.
