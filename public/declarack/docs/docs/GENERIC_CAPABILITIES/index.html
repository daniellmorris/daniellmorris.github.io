Generic resource capabilities¶

Declarack's core renders resources, executes declared operations and manages bounded sessions. Adapters own system-specific commands, transports and resource semantics. These capabilities use the same renderer for HTTP applications, Docker resources and SSH hosts.

Resource selectors¶

A feature can obtain choices from a read operation, map its response with JSONata, and bind the selection to a declared string/choice input of its inventory operation:

features:
  tutorial.team-applications:
    title: Applications by team
    operation: tutorial.team-apps.list
    rows: items
    selector:
      operation: tutorial.teams.list
      input: team
      label: Team
      rows: items
      value: id
      text: name
    columns:
      - {label: Application, value: name}
      - {label: Status, value: status}

The operation names are declared by the API tutorial. To try this, copy selectors.yaml into the folder from the dashboard tutorial, read source files and reload. Open Training API → Applications by team. Platform returns Catalog API and Queue worker; Product returns Customer portal. Changing the selection clears old rows and selection. Automatic inventory reloads; manual inventory waits for Collect.

selector.inputs supplies optional constant lookup inputs. rows, value and text are JSONata expressions. Choices must have unique nonempty string or safe integer identities (converted to strings for the selected operation input). At most 1,000 choices are loaded. An invalid lookup is shown as an error.

Use all: {value: all, label: All nodes} only when the inventory operation implements that value. A provider's published feature omits this option if its input constraints reject the value. The renderer does not implement aggregation; that belongs to the operation executor. Lookup operations cannot be on-demand or use mutating HTTP methods. The lookup must be available on the target for its selector to appear.

Workflow fields use the existing type: select and options_from contract. There is no separate node-picker component. Provider-conditional fields only grant their lookup operations on the matching provider.

String constraints¶

Operation input schemas use generic types and constraints:

inputs:
  resource:
    type: string
    pattern: '[a-z0-9]{12,64}'
  project:
    type: string
    min_length: 2
    max_length: 40

Patterns match the entire string. Length constraints are 0–512 characters; the default upper bound is 512. Constraints and default values are checked when loading configuration and submitted values are checked before execution. Docker/Swarm adapters declare their identifier constraints in their own operation YAML and check required executor constraints at registration. They are not core input types.

Interactive terminals¶

An action opts into the generic terminal view and declares its transport operations:

actions:
  - label: Open terminal
    operation: ssh.terminal.open
    icon: terminal
    terminal:
      title: SSH terminal
      description: Open an interactive session as the configured SSH user.
      read: ssh.terminal.read
      write: ssh.terminal.write
      resize: ssh.terminal.resize
      close: ssh.terminal.close
  - {label: Terminal read, operation: ssh.terminal.read, hidden: true}
  - {label: Terminal write, operation: ssh.terminal.write, hidden: true}
  - {label: Terminal resize, operation: ssh.terminal.resize, hidden: true}
  - {label: Terminal close, operation: ssh.terminal.close, hidden: true}

The built-in ssh_commands feature includes this action. Enable that feature on an SSH target to use it. The session runs as the configured SSH user, with the mounted identity and known-host validation already used by the SSH adapter. Shell choices are declared in the open operation's schema; opening a terminal is manual.

The renderer builds connection fields from the open operation's inputs, using label, default, choices, placeholder, numeric bounds and required state. action.row maps resource identity fields when needed. Remaining input fields become connection controls. cols and rows are reserved for terminal geometry. No shell, user, container-name or Docker path is built into the terminal component.

All five operations must be declared and enabled on the same feature/target:

Operation Protocol
Open Identity/connection fields plus cols, rows; returns session
Read session; returns base64 data and boolean closed
Write session, UTF-8 data
Resize session, cols, rows
Close session; closes the process and provider cleanup callback

Adapters construct argument arrays and pass an ownership scope to backend.terminal_sessions.Terminals. The PTY manager never constructs Docker or SSH commands. Docker scopes include target identity and connection; SSH scopes include target identity and SSH arguments. A session cannot be accessed through a different target. Input/output, concurrent sessions and idle time remain bounded. Swarm task terminals keep their node-local relay and cleanup inside the Swarm adapter; they do not SSH into workers.

File browsing¶

An action maps any required resource inputs and binds a list operation plus file_browser.read. Both operations must be declared as feature actions. The shared view understands file-tree responses rather than Docker volume records. file_browser.title customizes its heading.

List responses contain:

{
  "path": "",
  "items": [{"name":"hello.txt","path":"hello.txt","kind":"file","size":12,"mode":"-rw-r--r--"}],
  "total": 1,
  "offset": 0,
  "previous_offset": 0,
  "next_offset": null,
  "capabilities": {"read_only":true,"max_file_bytes":65536,"symlinks":false}
}

Read responses contain path, name, size, optional UTF-8 text and base64 base64. Pagination follows provider offsets. The view displays advertised limits; the executor must enforce them. The shared backend.file_tree.browse(root, ...) helper is descriptor-relative and refuses traversal, symlinks, devices and files over its 64 KiB bound. An adapter supplies the root; Docker mounts a volume at /volume in a short-lived helper. This refactor does not add SSH file browsing or file writes.

Related rows and collection status¶

children.expand_label supplies an expansion button label; children.identity is a JSONata expression for its parent title. Defaults say “Show related resources.” No Docker Spec.Name or container label is inferred by the shared row component.

A feature with per-resource collection results can map a status summary:

collection_status:
  title: nodes
  rows: nodes
  label: node_name
  error: error

The result shape belongs to the operation. Another adapter can use rows: hosts, label: hostname, and error: failure without changing the renderer.

Adapter ownership and schema changes¶

Docker/Swarm services are grouped by responsibility: stack sources/deployment in adapters/swarm/stacks.py, node jobs in adapters/swarm/jobs.py, inventory in adapters/docker/resources.py, and overview dispatch in adapters/swarm/workflows.py. The runtime module composes those services. They are exposed through an adapter blueprint and adapter executors. The HTTP host retains authentication, settings, operation dispatch, check/run endpoints and static assets. Stack databases and encryption keys continue using the configured data directory and target scope.

Connectors can supply bind(state, target_id, config) when registering their connection. It returns the target-specific runtime state; the core does not know how an adapter partitions its storage.

This is a pre-release schema cleanup. Update custom definitions directly:

  • Replace docker_id and volume_name with type: string and the desired pattern.
  • Replace a bare selector operation string with the selector mapping above.
  • Replace type: node-picker with type: select and options_from.
  • Import the generic PTY manager from backend.terminal_sessions and supply a command explicitly; use backend.file_tree for the rooted file helper.
  • Rebuild and load the same updated agent image on Swarm nodes when updating the controller. Node helpers must have the matching module paths.

Feature navigation icons use an explicit icon setting (for example server, layers, drive, activity or file) rather than interpreting feature IDs.

No runtime package dependencies or Docker image stages were added.
