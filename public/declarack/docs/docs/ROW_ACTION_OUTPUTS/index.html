Action output placement and viewers¶

Actions can display a result beneath the resource that produced it, in the page, or in a dialog. This is a shared renderer contract: Docker, Swarm, SSH and HTTP adapters return data; feature YAML chooses the presentation. No adapter-specific React component is needed.

Configure an inline row result¶

Add a stable identity and an output action to an existing feature:

features:
  applications:
    title: Applications
    operation: apps.list
    rows: items
    selection_key: id
    columns:
      - {label: Name, value: name}
    actions:
      - label: Metrics
        operation: apps.metrics
        row: {id: id}
        immediate: true
        output: $
        presentation:
          placement: row
          viewer: structured
      - label: Inspect JSON
        operation: apps.inspect
        row: {id: id}
        immediate: true
        output: json
        presentation: {placement: row, viewer: json}

This is a feature fragment. Define the apps.list, apps.metrics and apps.inspect operations with bindings for your adapter, then enable applications on the target. List results in this example have an items array with unique string or integer id fields. The two action operations accept id. See the API interface tutorial for connection and operation setup.

Synthetic HTTP example: the result belongs to Alpha, rather than the page header.

Clicking Metrics opens the result directly underneath that application's row. Inspect JSON replaces that row's metrics panel. Another row can have its own independent result open at the same time. A close control hides each panel.

Contract¶

Setting Values / behavior
presentation.placement row, page (default), or dialog
presentation.viewer structured, json, or text; default is json for output: json, otherwise text
output: '$' Pass the entire returned value to the viewer, preserving types
output: json Pass the entire returned value; defaults to the searchable JSON inspector
output: FIELD Pass a direct result property to the viewer; this is not JSONata
immediate: true Execute directly when clicked, using configured row/selection inputs

structured shows top-level fields and expandable nested values. json reuses the searchable tree/text inspector with copy and download controls. text preserves text formatting and serializes objects as JSON. Viewers grow with their content up to 80% of the viewport height, then scroll. Use Expand height to show the complete result at its natural height, and Limit height to restore the scrollable limit; they do not mask fields or truncate the returned payload. Missing or empty text output is reported explicitly, rather than inventing data.

For a page result, use presentation: {placement: page, viewer: text}. For an output dialog, use presentation: {placement: dialog, viewer: json}. Placement does not change the adapter operation, authorization or confirmation requirements. An output dialog is a result viewer, not an extra confirmation step.

Row identity and lifetime¶

A row result requires row input bindings and a stable identity supplied by selection_key, details.row_id, or children.row_id (in that order). Identity paths support dotted fields and must resolve to a unique nonempty string or a safe integer. Zero is a valid identity. For node-local resources, use a key containing both node and resource identity; a volume name alone is not unique across nodes.

Sorting, filtering and pagination do not reassign results to another row. Hidden rows retain their result while you navigate the same loaded inventory. A fresh inventory collection, selector change or route change clears results. Closing a panel or starting a different output action for the same row invalidates older responses, so a slow response cannot reopen or overwrite it. Closing hides the result; it does not undo or cancel a server-side operation already submitted.

Loading and action failures appear in the row panel. An inline read does not block actions on other rows. It does not trigger an automatic inventory reload. Existing related-resource expansion remains available independently.

Row placement is for list actions. It cannot be combined with detail: true, back, result: replace, bulk actions, terminals or file browsers. Page and dialog placement are available for ordinary output actions, including detail views. Every explicit presentation requires output. Invalid settings are rejected when configuration is loaded.

Actions without presentation retain page-level output. Dedicated resource detail pages remain accessible through resource links. Confirmed actions still use their declared confirmation; do not set immediate on actions that require confirmation.

Bundled usage¶

Container stats use structured inline output. List-row Inspect JSON actions for containers, images, networks, volumes, Swarm services, nodes, tasks, configs and secrets use inline JSON output. Detail-page inspection stays in the page. Volume keys retain node ownership, and Swarm child-container expansion is independent of action output.
