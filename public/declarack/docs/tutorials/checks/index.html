Schedule a readiness check¶

Outcome: a scheduled read with consecutive failure/recovery thresholds and persisted result history. Start with the folder from the dashboard tutorial. Only the Training API is required for this check.

1. Add the check fragment¶

cp examples/tutorial-api/checks.yaml /tmp/declarack-tutorial-config/20-checks.yaml

In Declarack Settings, choose Review import from files, inspect the diff, and select Import & activate. Alternatively restart the tutorial with FORCE_LOAD=1. The fragment is:

checks:
  tutorial-readiness:
    title: Training API readiness
    target: training
    operation: tutorial.health
    healthy: status = "ok"
    every: 10s
    failure_threshold: 2
    recovery_threshold: 1

tutorial.health is already declared in the base tutorial configuration with check_safe: true and a GET binding for /health. You can omit operation for a connector-level connection check instead. A scheduler operation must be an eligible read or explicitly check-safe; mutating HTTP/Docker methods are refused.

2. Inspect the first result¶

Open Checks, select Training API readiness, and choose Run now. A successful JSON response with status: ok should make the check healthy. Its history and last-success information appear on the detail page.

Definitions live in YAML. Runtime results, current state and operator pauses live in the shared database (state.sqlite under the data directory by default). The tutorial's /tmp data path is for local training; use a persistent deployment volume for production.

3. Trigger and recover from failure¶

Stop the Training API with Ctrl+C. Choose Run now twice, waiting for each result to finish, or allow two scheduled runs. The latest result fails immediately, but a prior healthy state can remain until the second consecutive failure reaches the configured threshold. Then the check becomes failing.

Restart the API:

python3 examples/tutorial-api/server.py

Choose Run now again. One successful result meets the recovery threshold and returns the check to healthy. The API's example restart counters reset because its data is in memory; Declarack's check history remains in its separate data directory.

4. Pause deliberately¶

Pause and resume the check from its detail page. Pause is persisted separately from YAML enabled: false; it survives a controller restart. Paused or disabled checks cannot be run manually. A run already in flight may finish.

These transitions are local alarms and recovery records. Declarack currently sends no email/webhook notifications and has no maintenance windows or uptime-percentage calculation. Do not interpret this tutorial as outbound alert delivery.
