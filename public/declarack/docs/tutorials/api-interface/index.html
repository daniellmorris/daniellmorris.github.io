Build your first API administration interface¶

Outcome: a working application table, detail pages, confirmed row/bulk actions, and a form whose application choices depend on the selected team. You need a repository checkout, Python 3.12+ and Node 22.12+. No Docker engine is required.

This tutorial uses an actual local HTTP server with synthetic data. Its restart endpoint increments a counter; it does not restart real applications. All state in that API resets when the training server restarts.

1. Install and build Declarack¶

From the repository root:

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build

If you already have that development environment, reuse it. The example files are the training server and the complete system configuration.

2. Start the training API¶

In one terminal:

python3 examples/tutorial-api/server.py

Keep it running. In another terminal, verify the response:

curl http://127.0.0.1:9010/apps

You should receive an object with an items array containing Catalog API, Queue worker and Customer portal. Each record has id, name, team, status and restarts. Two records are running and one is stopped.

3. Start a separate Declarack instance¶

In the second terminal, from the repository root:

DECLARACK_CONFIG=examples/tutorial-api/declarack.yaml \
DECLARACK_CONFIG_FORCE_LOAD=1 \
DECLARACK_DATA=/tmp/declarack-tutorial-data \
DECLARACK_PASSWORD='choose-a-local-tutorial-password' \
PORT=9081 .venv/bin/python -m backend.server

Open http://127.0.0.1:9081, sign in as admin, and use your chosen password. Select Training API → Applications. This instance uses port 9081 so it can coexist with the real lab on 9080 and a normal installation on 8080.

These loopback URLs assume both Python processes run on your host. Inside a Docker container, 127.0.0.1 identifies that container, so do not copy this origin unchanged into a container deployment. Use a reachable container-network/host address there.

4. Understand the table¶

The checked-in file connects the target to an enabled feature:

targets:
  training:
    label: Training API
    connection: http
    base_url: http://127.0.0.1:9010
    features: [tutorial.apps]

A named operation supplies data. The provider binding says how to retrieve it:

operations:
  tutorial.apps.list:
    bindings:
      http: {executor: http.request, path: /apps}

The feature extracts rows with JSONata and chooses their columns:

operation: tutorial.apps.list
rows: items
columns:
  - {label: Application, value: name}
  - {label: Team, value: team}
  - {label: Status, value: status}
  - {label: Restarts, value: restarts}

Click headers to sort, filter by Status, search by name and export the resulting rows. Exports include filtered rows beyond the current page. JSON exports contain the mapped records; CSV uses the visible columns.

5. Open details and run an action¶

Click Catalog API to see its dedicated detail page, then return to the list. Use its Restart example app row action and confirm the message. Refresh if needed: its restart counter should increase by one.

The operation maps a validated id into an encoded path and sends a POST request. The feature's row: {id: id} supplies the selected record's identity. The installed example also enables bulk: true: select two rows and review the eligible resources before confirming. Results appear in the global Operations view.

The API server—not JSX—owns the training state change. In your own integration, the operation would call your actual management API with its own authorization and resource checks.

6. Try dependent dropdowns¶

Choose Restart by team above the table:

  1. Select Platform. The application field loads Catalog API and Queue worker.
  2. Select Catalog API, then switch the team to Product.
  3. The application value clears and its choices become Customer portal.
  4. Select Customer portal and confirm the training action.

The field definitions use options_from, with the second field depending on team and mapping form.team into a read-operation input. The lookup features establish read roles but are not enabled in navigation. This shows how a form can query supporting resources without adding extra sidebar views.

Dynamic form reference explains manual sources, stale requests and validation.

7. Customize it¶

Copy the complete configuration before adapting it for a real API. Change the origin, resource paths, response mappings, columns and operation schemas. Use a mounted bearer credential reference with HTTPS where required. Do not send actual credentials to the unauthenticated training server.

After external YAML edits, use Settings → Review import from files → Import & activate, or restart this tutorial process (FORCE_LOAD imports files at startup). For GUI file creation and integration setup, switch to folder configuration.

Next: keep these processes running and build a dashboard across two targets, then add scheduled checks. Stop either process with Ctrl+C when finished. The tutorial data directory is separate from your regular installation; its persisted run/check history can be kept for a later session.
