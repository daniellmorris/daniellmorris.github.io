Build a dashboard across targets¶

Outcome: one custom page showing counts, a grouped bar chart and two resource tables from independent APIs. Complete the first tutorial first. Keep the training API on port 9010 running.

1. Start a second API¶

In another terminal:

python3 examples/tutorial-api/server.py --port 9011 --label Staging

These are separate in-memory datasets. An action on port 9010 does not change the counters returned by port 9011.

2. Assemble a configuration folder¶

From the repository root:

mkdir -p /tmp/declarack-tutorial-config
cp examples/tutorial-api/declarack.yaml /tmp/declarack-tutorial-config/00-api.yaml
cp examples/tutorial-api/dashboard.yaml /tmp/declarack-tutorial-config/10-dashboard.yaml

If you used this folder in an earlier session, inspect its other YAML files first: all visible YAML fragments participate in the merge. Stop only the tutorial Declarack process on port 9081, then restart it with the folder:

DECLARACK_CONFIG=/tmp/declarack-tutorial-config \
DECLARACK_CONFIG_FORCE_LOAD=1 \
DECLARACK_CONFIG_EDIT=1 \
DECLARACK_DATA=/tmp/declarack-tutorial-data \
DECLARACK_PASSWORD='choose-a-local-tutorial-password' \
PORT=9081 .venv/bin/python -m backend.server

The new fragment adds staging and reuses the existing tutorial.apps feature. Its environment target list replaces the original one with [training, staging]. The complete fragment is ready to inspect.

3. Open Application overview¶

The custom page is available at the workspace level and through the Tutorial environment. It should show six applications in total and, for each target, two running applications out of three.

Its source definitions name the target and read operation explicitly:

sources:
  training: {target: training, operation: tutorial.apps.list}
  staging: {target: staging, operation: tutorial.apps.list}

Each source result becomes data.<source-name>. Sources also expose loading, availability and collection state under sources.

4. Read the chart mapping¶

The chart first creates category rows from both API responses, then maps values from each category into series:

type: bar
sources: [training, staging]
rows: >-
  [{"target":"Training","running":$count(data.training.items[status="running"]),"total":$count(data.training.items)},
   {"target":"Staging","running":$count(data.staging.items[status="running"]),"total":$count(data.staging.items)}]
x: target
series:
  - {label: Running, value: running}
  - {label: Total, value: total}

Use this pattern for Docker, SSH or another HTTP source; the renderer does not know what an application or target count means. Line charts require ordered numeric samples supplied by a source. Declarack does not accumulate chart history itself.

The two table panels link to their corresponding target's detail pages and support search, sorting, page-size selection and CSV/JSON export.

5. Observe a partial failure¶

Stop only the Staging API with Ctrl+C, then refresh the custom page. Staging should be unavailable. The combined card/chart cannot claim a complete result; the Training panel can still show its own successfully collected source. Missing data is not a healthy empty list or a zero count.

Restart Staging with the same command and refresh again. Turn on browser auto-refresh if useful, then turn it off when finished. It does not run while the page is closed, and it does not collect manual/on-demand sources automatically.
